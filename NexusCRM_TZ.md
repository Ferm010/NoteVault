## 1. Общие положения

### 1.1. Цель проекта

Разработка no-code CRM-платформы NexusCRM с визуальным конструктором сущностей и автоматизаций, позволяющей бизнесу любого масштаба самостоятельно настраивать систему под свои процессы без привлечения разработчиков. Платформа включает веб-приложение, мобильное приложение (cross-platform), интеграцию с мессенджерами, AI-ассистента, конструктор ботов и гибкие настройки хранения данных.

### 1.2. Ключевые принципы

- **No-code** — все настройки через визуальный интерфейс
- **Быстрый старт** — шаблоны для быстрого развёртывания
- **Гибкое хранение** — локальное или облачное на выбор
- **152-ФЗ** — полное соответствие законодательству РФ о персональных данных
- **Масштабируемость** — от самозанятого до среднего бизнеса

### 1.3. Конкурентные преимущества

| Преимущество | Описание |
|---|---|
| Визуальный конструктор сущностей | Создавай любые объекты без кода |
| Конструктор автоматизаций | if/then сценарии без программирования |
| AI-ассистент | Автозаполнение, классификация, подсказки |
| Локальное хранилище | Установка на своё оборудование |
| Мульти-бот | Telegram, WhatsApp, Max из одной панели |
| Импорт из любых источников | Excel, CSV, Google Sheets, 1С, другие CRM |
| Пробный период 21 день | Полный доступ без ограничений |

## 4. Архитектура системы

### 4.1. Микросервисы

```
┌─────────────────────────────────────────────────────────────┐
│                      API Gateway (Nginx)                    │
└──────────┬──────────┬──────────┬──────────┬────────────────┘
           │          │          │          │
    ┌──────▼────┐ ┌──▼─────┐ ┌─▼──────┐ ┌▼──────────┐
    │ Auth      │ │ CRM    │ │AI      │ │Integration│
    │ Service   │ │ Core   │ │Service │ │ Service   │
    └──────┬────┘ └──┬─────┘ └─┬──────┘ └┬──────────┘
           │          │          │          │
    ┌──────▼──────────▼──────────▼──────────▼──────────┐
    │              PostgreSQL + Redis + MinIO           │
    └──────────────────────────────────────────────────┘
           │          │          │
    ┌──────▼────┐ ┌──▼─────┐ ┌─▼──────────┐
    │ Workflow  │ │Notify  │ │ Analytics  │
    │ Engine    │ │ Service│ │ Service    │
    └───────────┘ └────────┘ └────────────┘
```

### 4.2. Сервисы

| Сервис | Назначение |
|---|---|
| **auth-service** | Регистрация, логин, JWT, OAuth2, 2FA |
| **crm-core** | CRUD сущностей, контактов, сделок, задач |
| **workflow-engine** | Выполнение автоматизаций (if/then) |
| **ai-service** | Провайдеры AI, кэширование, классификация |
| **integration-service** | Коннекторы мессенджеров, платёжек, складов |
| **analytics-service** | Агрегация данных, отчёты, дашборды |
| **notification-service** | Email, push, Telegram, WhatsApp, SMS |
| **file-storage** | Загрузка и хранение файлов |
| **bot-manager** | Управление ботами в мессенджерах |
| **import-service** | Импорт из внешних источников |

### 4.3. Протоколы взаимодействия

- **REST API** — клиент ↔ сервер
- **gRPC** — межсервисное общение
- **WebSocket** — real-time обновления
- **Webhook** — внешние интеграции

### ЗАДАЧА 1: Проектирование архитектуры

**Описание:** Создание фундаментальной архитектуры системы. Определяет структуру данных, сервисов, протоколов и процессов разработки.

#### 1.1. ER-диаграмма базы данных
- Проектирование таблиц: `users`, `organizations`, `entities`, `fields`, `contacts`, `companies`, `deals`, `tasks`, `activities`, `roles`, `permissions`, `automations`, `integrations`, `documents`, `files`, `audit_logs`, `import_jobs`
- Связи между таблицами (foreign keys)
- Индексы для производительности поиска
- JSONB-поля для гибких данных конструктора сущностей

#### 1.2. Схема микросервисов
- Определение границ каждого из 10 сервисов
- Ответственность каждого сервиса
- Точки взаимодействия между сервисами
- SLA для каждого сервиса

#### 1.3. API-контракты (OpenAPI/Swagger)
- Описание всех REST-эндпоинтов
- Форматы запросов и ответов
- Коды ответов и ошибки
- Автоматическая генерация документации

#### 1.4. WebSocket-протоколы
- Подключение и аутентификация по WebSocket
- Форматы событий (создание, обновление, удаление записей)
- Подписка на каналы (organization, user, entity)
- Обработка разрывов соединения

#### 1.5. CI/CD пайплайн
- GitHub Actions / GitLab CI
- Линтинг, тесты, сборка на каждый PR
- Автоматический деплой в staging
- Ручное подтверждение для production
- Rollback при неудачном деплое

#### 1.6. Docker Compose для локальной разработки
- Все сервисы в одном docker-compose.yml
- PostgreSQL, Redis, MinIO, Nats
- Vite-сервер для фронтенда
- Hot-reload для разработки

### ЗАДАЧА 2: Сервис аутентификации и авторизации

**Описание:** Обеспечение безопасного доступа пользователей к системе с поддержкой многофакторной аутентификации и OAuth2.

#### 2.1. Регистрация / логин
- Email + пароль (минимум 8 символов, сложность)
- Хэширование паролей (bcrypt, cost factor 12)
- Проверка уникальности email
- Верификация email (ссылка с токеном)
- Ограничение попыток входа (rate limiting)

#### 2.2. JWT-токены
- Access-токен (живёт 15 минут)
- Refresh-токен (живёт 30 дней)
- Подпись через HMAC-SHA256
- Blacklist для refresh-токенов при выходе
- Автоматическое обновление access-токена

#### 2.3. OAuth2 провайдеры
- Google (Google Sign-In)
- Яндекс (Яндекс.ID)
- GitHub (для разработчиков)
- Redirect URI и callback обработка
- Синхронизация профиля

#### 2.4. Двухфакторная аутентификация
- TOTP (Google Authenticator, Authy)
- SMS-код (через SMS-шлюз)
- Резервные коды для восстановления
- Настройка в профиле пользователя

#### 2.5. Ролевая модель (RBAC)
- Владелец — полный доступ к организации
- Админ — управление настройками и пользователями
- Менеджер — работа с записями
- Наблюдатель — только чтение
- Пользовательские роли (настраиваемые)

#### 2.6. Восстановление пароля
- Запрос ссылки на email
- Токен сессии (живёт 1 час)
- Смена пароля через форму
- Уведомление о смене пароля

#### 2.7. Логирование входов и сессий
- IP-адрес, устройство, браузер
- Время входа/выхода
- Активные сессии (просмотр и завершение)
- Подозрительная активность (алерты)

### ЗАДАЧА 3: Конструктор сущностей (no-code)

**Описание:** Визуальный инструмент для создания кастомных объектов CRM без программирования. Пользователь определяет структуру данных и логику.

#### 3.1. Создание кастомных объектов
- Название объекта (например, «Поставщики», «Курсы»)
- Иконка (библиотека иконок)
- Описание
- Цветовая схема
- Количество создаваемых объектов (ограничение по тарифу)

#### 3.2. Типы полей
- **Текст** — однострочный, многострочный
- **Число** — целое, дробное, с точностью
- **Дата** — дата, время, дата+время
- **Чекбокс** — да/нет
- **Выпадающий список** — одиночный выбор
- **Мульти-селект** — множественный выбор
- **Файл** — загрузка документов
- **Ссылка** — URL
- **Email** — валидация email
- **Телефон** — валидация номера
- **Пользователь** — привязка к юзеру CRM
- **Формула** — вычисляемое поле

#### 3.3. Валидация полей
- Обязательные поля
- Уникальность значений
- Диапазон чисел (мин/макс)
- Паттерн для текста (regex)
- Зависимые поля (show/hide logic)

#### 3.4. Связи между сущностями
- **1:1** — одна к одной
- **1:N** — одна ко многим
- **N:M** — многие ко многим
- Каскадное удаление
- Каскадное обновление

#### 3.5. Настройка внешнего вида карточек
- Layout карточки (grid, list)
- Порядок отображения полей
- Группировка полей
- Цветовая кодировка по статусу
- Шаблоны карточек

#### 3.6. Шаблоны сущностей
- **Продажи** — контакты, компании, сделки, задачи
- **Услуги** — клиенты, проекты, этапы, финансы
- **HR** — кандидаты, вакансии, собеседования
- **Логистика** — отправления, маршруты, водители
- **Образование** — студенты, курсы, оценки
- **Недвижимость** — объекты, клиенты, сделки

#### 3.7. Экспорт/импорт сущностей
- Экспорт в JSON (полная схема)
- Импорт из JSON
- Перенос между организациями
- Версионирование схем

#### 4.7. Поиск и фильтры
- Глобальный поиск (по всем сущностям)

- Фильтры по дате

#### 4.8. Табличный вид

- Выбор отображаемых столбцов
- Группировка данных
- Итоги (сумма, среднее, количество)

### ЗАДАЧА 5: Задачи и календарь

**Описание:** Система управления задачами с привязкой к записям CRM и календарём.

#### 5.1. Создание задач
- Название, описание
- Дедлайн (дата + время)
- Ответственный (пользователь)
- Приоритет (высокий, средний, низкий)
- Статус (новая, в работе, выполнена, просрочена)
- Привязка к контакту/сделке/компании

#### 5.2. Привязка задач к контактам/сделкам
- Связь через foreign key
- Просмотр задач на карточке
- Создание задачи из карточки
- Автоматическое создание по автоматизации

#### 5.3. Календарь
- Виды: месяц, неделя, день
- Отображение задач и встреч
- Drag & drop для переноса
- Создание события
- Цветовая маркировка по типу

#### 5.4. Напоминания
- Push-уведомления
- Email-напоминания
- Telegram/WhatsApp-уведомления
